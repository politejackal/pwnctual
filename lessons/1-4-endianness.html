Many things inside the memory, like numbers, addresses, etc., are more than one byte long.

Recall a byte is something like 0x41, and numbers are usually 4 bytes long, so inside the memory they would be stored as something like 0x12345678 or 0x7ffe16292f84. As you can see, these are longer than 2 hex digits, i.e. one byte.

First, notice the 2 ends of a value like 0x1234567890ab. Of course these are 6 bytes, since 2 hex digits represent one byte. So these are the 2 ends of this value: the first byte is 12, and the last byte is ab, these are the two ends.

Now imagine a random number like 1000000, if you change the leftmost digit, it goes from one million to two million, notice that this change is very big. Built on this same concept, in the hex value 0x1234567890ab too, the byte 12 is the most significant byte. In terms of computer science, this is known as the Most Significant Byte. However, if you change the rightmost digit, it just changes the value by one. Since the change is small, the byte on this end or the rightmost end is known as the Least Significant Byte.

Now you see, when a value like 0x1234567890ab is stored in memory, in CPUs which follow the little endian mechanism (which is followed by almost all devices in the world):

  1. The CPU takes the last byte, or 2 hex digits, and puts it inside the new memory address like 0xab.
  2. Then it takes the next last byte from the original value and puts it at the end of this new address, which then becomes 0xab90.
  3. And so on, until the new memory address becomes 0xab9078563412.
Original value:   0x 12 34 56 78 90 ab
                     ↓  ↓  ↓  ↓  ↓  ↓
Stored in memory:    ab 90 78 56 34 12

Notice how every byte is being stored in a reversed order.

This phenomenon is very useful for various reasons that you can google. I’m really not good at convincing people that endianness is very important, but there certainly are people out there who are good at it, so feel free to pause and check it out if you are curious!

Now also do notice that every 2 hex digits are being replaced, not every single character though. This is important and many people confuse this!

However, saving it in reverse order happens only in the CPUs which follow little-endianness. Though most devices follow this, some, and I mean really some small amount of devices follow something called big-endian, which saves the value as is. Though this creates many problems, it exists, just so you know.

Does endianness affect strings?

No. A string in C is not a single multi-byte number. It is a sequence of individual 1-byte characters. If you store HACK in memory at 0x1337, the H is stored at 0x1337, the A at 0x1338 and so on, on both the little-endian systems as well as the CPUs which follow big-endian. So it doesn't affect strings, alright!

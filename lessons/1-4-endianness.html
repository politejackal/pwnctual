Suppose we want to store the 4-byte hexadecimal number 0xDEADBEEF into RAM starting at address 0x1000.

First, split it into its 4 individual bytes (remember, 2 hex digits = 1 byte):

DE | AD | BE | EF
  • DE is on the far left—just like the "thousands" place in the number 5,432, it carries the largest weight. We call it the Most Significant Byte (MSB), or the "Big End".
  • EF is on the far right—like the "ones" place. We call it the Least Significant Byte (LSB), or the "Little End".

There are two ways a CPU can pack those 4 bytes into memory boxes 0x1000 through 0x1003:

  • Big Endian (Human Order): The Big End (DE) goes into the first memory address (0x1000). This is used in network traffic (TCP/IP headers).
  • Little Endian (x86/x64 & ARM CPU Order): The Little End (EF) goes into the first memory address (0x1000). Almost every laptop, desktop, server, and smartphone CPU you will ever hack uses Little Endian.

Crucial Detail: Look closely at the Little Endian column. Notice that 0xDEADBEEF became EF BE AD DE—NOT FE EB DA ED. You never flip the characters inside a byte; you only reverse the order of the bytes.
bug_report
Why Hackers Care: Suppose you find a secret admin function in a program located at memory address 0x080484b6. To trick the program into jumping there, you must inject that address into RAM in Little Endian order—byte by byte, backward: \xb6\x84\x04\x08. If you send it forward, the CPU will try to jump to 0xb6840408 and immediately crash.

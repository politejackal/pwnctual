You might have heard that computers are just ones and zeroes. That sounds impossible but is actually true! At the physical level, your device's processor and RAM (memory) are actually made up of billions of tiny switches, called transistors.

A switch has only 2 states. Either ON or OFF. In terms of computer science, we represent this with 1 or 0. 1 for ON and 0 for OFF.

toggle_offOFF= 0
toggle_onON= 1

Now you can imagine that we might be able to use a certain sequence of 0s and 1s to represent various things. It turns out that computer scientists did exactly this. Simple as that.

In fact, every single piece of data on your device, whether it is a movie, a password, or a voice note, is all just a bunch of 0s and 1s in a sequence. This sequence of 0s and 1s is called binary.

Core units of data

  1. A bit (a binary digit): A single 1 or 0. The same thing I just mentioned earlier. A switch either ON or OFF. Example: 1.
  2. A nibble: A group of four switches, four 0s and 1s in a row. Example: 1011.
  3. A byte: A group of 8 switches or bits. Example: 10110101.
shield
The hacker's first law of memory: In C and modern computer architecture, 1 byte is the smallest addressable unit. You cannot point to a single bit in memory and change it, though there are workarounds which we will learn later in this course.

How to read an 8-bit byte

So far we have discussed what binary is and how you write it. Now let's learn to read it. However, before learning to read a computer's number system, let's recall our normal everyday number system from grade school. In normal everyday life, we use decimal or base-10. Base-10 sounds cryptic but all it means is that in each column, like for the number 123, a hundred and twenty-three, each digit from right to left increases in value by 10. Like the 3 is in the ones place and the 2 is in the tens place and the 1 is in the hundreds place. Each digit's column from right to left is multiplied by 10.

Okay, that was simple. Now what would happen if instead of multiplying each digit from right to left with 10, we multiplied by 2? Well, you would get base-2! I know you didn't understand shit, so let's slow down and look at what's going on!

So imagine you have the binary number 1011. You would start by multiplying the rightmost number, the 1, with 1, because recall from grade school and in fact in your mind, that's what you are actually doing under the hood, in decimal.

You do the following in your brain:

Place...1000s100s10s1s
Digit...1011
Multiply...1 × 10000 × 1001 × 101 × 1
Add up1000 + 0 + 10 + 1 = 1011

Now the same idea, but instead of multiplying with 10, multiply with 2.

Place...8s4s2s1s
Digit...1011
Multiply...1 × 80 × 41 × 21 × 1
Add up8 + 0 + 2 + 1 = 11

So to convert a binary byte like 01000001 into a normal number, just add up the column values where a 1 is switched ON:

Bit Value (Place)1286432168421
Binary Byte01000001

In the starting example, 01000001:

  • Only the 64 column and the 1 column are turned on (1).
  • Now you add the columns which are turned on. 64 + 1 = 65.
  • So 01000001 in binary equals 65 in decimal (which also happens to be how the capital letter 'A' is stored inside a computer, it's just that a standard called ASCII decided that 65 in binary would mean the letter A).

If all 8 bits are turned off (00000000), the value is 0. If all 8 bits are turned on (11111111), you add 128 + 64 + 32 + 16 + 8 + 4 + 2 + 1, which equals 255. Therefore, a single byte can hold a value anywhere from 0 to 255.

Why does a hacker care?

What happens if a byte is holding 255 (11111111) and the program adds 1 to it? It tries to become 256 (100000000), which takes 9 bits. Since a single byte only has 8 bits, the 1 falls off the left edge, wrapping the byte all the way back around to 00000000 (0).

You just discovered your first vulnerability class: an Integer Overflow. We will come back to this later.

How RAM Works: Addresses vs. Values

When you run a program, the CPU needs a fast, temporary workspace to hold all the numbers, text, and instructions it is currently working on. That workspace is a physical chip in your computer called RAM (Random Access Memory).

Think of RAM as a single, massive street lined with billions of identical post office boxes. To understand how a computer stores data—and how hackers manipulate it—you must separate two concepts that beginners constantly mix up: the Address and the Value.

1. The Memory Address (Where the box is)

  • Every single byte-sized box in RAM has a permanent, unique number painted on the outside so the CPU can find it.
  • This label is the Memory Address.
  • Addresses start at 0x0000 and count upward one by one (0x1000, 0x1001, 0x1002, 0x1003, and so on).
  • An address is not the data itself; it is just the location in RAM where a single byte of data lives.

2. The Value (What is inside the box)

  • Inside every memory address sits the actual data.
  • This data is the Value.
  • The Strict Size Limit: Every single address box in RAM holds 1 Byte (8 bits, or 2 Hex digits)—never more, never less.
  • Because 1 byte is 8 bits (00000000 to 11111111), a single box in RAM can only hold a number between 0 and 255 (in Hex: 0x00 to 0xFF).

How Does RAM Store Text If It Can Only Hold Numbers?

Wait—if a RAM box can only hold a number from 0 to 255, how does a computer store your username or a password?

Decades ago, computer engineers created a standard lookup chart called ASCII. They assigned every English letter, digit, and keyboard symbol a specific number between 0 and 127:

  • The capital letter 'A' is assigned the number 65 (0x41 in Hex).
  • The capital letter 'B' is assigned the number 66 (0x42 in Hex).
  • The capital letter 'H' is assigned the number 72 (0x48 in Hex).
  • The number 0 (0x00 in Hex) is reserved as a special stop sign called a Null Byte. Whenever a program reads text from RAM, it reads one box after another until it hits a box containing 0x00, which tells the CPU: "The text ends right here."

Because every letter on your keyboard is represented by a small number under 255, one single letter fits inside one single RAM box (1 Byte).

How Does RAM Store Numbers Larger Than 255?

If a single box in RAM maxes out at 255 (0xFF), how does your computer store a larger number, like 50,000 or the 8-digit hex number 0xDEADBEEF?

It cannot fit a large number into a single box. Instead, the computer chains neighboring boxes together and treats them as one big container:

  • 1 Box (1 Byte / 8 bits): Holds a number up to 255 (0xFF).
  • 2 Neighboring Boxes (2 Bytes / 16 bits): Holds a number up to 65,535 (0xFFFF).
  • 4 Neighboring Boxes (4 Bytes / 32 bits): Holds a number up to 4,294,967,295 (0xFFFFFFFF).
  • 8 Neighboring Boxes (8 Bytes / 64 bits): Holds a massive number up to 18 quintillion (0xFFFFFFFFFFFFFFFF).

(In a later chapter, when we begin writing C code, you will learn the exact C keywords used to reserve 1 box, 2 boxes, 4 boxes, or 8 boxes in RAM).

The "Starting Address" Rule

When a large 4-byte number like 0xDEADBEEF is stored in RAM across 4 neighboring boxes—say, boxes 0x1000, 0x1001, 0x1002, and 0x1003—how does the CPU talk about where that number lives? Does it list all four addresses every time?

No. The CPU always refers to a multi-byte value by its first (lowest) memory address (0x1000).

  • It knows the value starts at 0x1000.
  • It knows the value is 4 bytes long, so it automatically grabs 0x1000 plus the next three boxes (0x1001, 0x1002, and 0x1003).

And because that 4-byte number has to be chopped up into 4 individual 1-byte pieces (DE, AD, BE, and EF) to fit into those 4 separate boxes, the CPU has to decide which piece goes into box 0x1000 first—which is the exact reason Endianness (next chapter) exists.

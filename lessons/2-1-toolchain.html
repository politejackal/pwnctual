In Chapter 1, I said that computers are all ones and zeroes. That’s freaking true! They don’t know what the hell abc is. They just know whether electricity is flowing or not.

But in C, we aren’t typing zeroes and ones, so how the hell will the CPU know what we mean? This is where things get interesting, for me at least.

Your C file is stored as ones and zeroes too, but they’re the wrong ones. They represent text, and the CPU doesn’t read text. It only understands machine code, which is instructions written as specific patterns of ones and zeroes.

It turns out that your C file goes through several stages until it becomes machine code. Each stage takes a file in and gives a new file out, and the C file you wrote stays untouched. The final file is called the executable, or the program. That’s what the CPU runs.

Here is an analogy: think of the different stages your C code goes through as stations. In this topic, we will be discussing the various stations our C code goes through to give us the machine code we want. The good thing is that we can stop at any station, grab the output at that stage and inspect it. Simple as that.

StationTakes inGives outIts job in life
1. Preprocessor hello.c (C text) hello.i (C text) It handles special lines starting with #, and removes all comments (things which don’t affect the program at all, just as labels on stuffed toys, just for humans to read).
2. Compiler hello.i (C text) hello.s (assembly text) Translate C into assembly.
3. Assembler hello.s (assembly text) hello.o (bytes) Turn every assembly instruction into its machine code bytes.
4. Linker hello.o + libraries hello (a program) Glue your code together with code you didn’t write (like the code that makes printf work) into one finished program you can run.

In Chapter 1, I said that computers are all ones and zeroes. That’s freaking true! They don’t know what the hell abc is. They just know whether electricity is flowing or not.

But in C, we aren’t typing zeroes and ones, so how the hell will the CPU know what we mean? This is where things get interesting, for me at least.

It turns out that your C file undergoes lots and lots of modifications until it’s a bunch of zeroes and ones. Yes, that’s the final file, known as the program, and it is a bunch of ones and zeroes. And that’s what the CPU runs.

Here is an analogy: think of the different things the C program undergoes as stations. In this topic, we will be discussing the various stations our C file goes through to give us the ones and zeroes we want. The good thing is that we can stop at any station and get the code at that stage and inspect it. Simple as that.

StageTakes inGives outIts one job in life
Preprocessor Your C file (.c) Expanded C file (.i) Pastes in the #include files, swaps in the #define values and removes comments.
Compiler Expanded C file (.i) Assembly (.s) Turns C into assembly instructions for your CPU.
Assembler Assembly (.s) Object file (.o) Turns assembly into machine code, the ones and zeroes.
Linker Object files (.o) The program Joins your object files with library code, like printf, into one program you can run.

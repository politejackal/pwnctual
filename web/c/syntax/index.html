C syntax

The grammar of C: the rules every line of C code has to follow.

Every language has grammar. In English, a sentence starts with a capital letter and ends with a full stop. If you break those rules, people still understand you most of the time.

C has grammar too, and it is called syntax. The difference is that C is not forgiving at all. The program that turns your C code into something the computer can run is called the compiler, and if you break one single rule, the compiler refuses to do its job and gives you an error instead.

So before we write anything useful, let’s learn the rules.

Your first C program

Here is the smallest useful C program. It prints Hello, world! on the screen. Don’t worry if it looks strange, we will go through it line by line.

hello.c#include <stdio.h>

int main(void) {
    printf("Hello, world!\n");
    return 0;
}
OutputHello, world!
LineWhat it means
#include <stdio.h> Brings in stdio.h, the standard input and output library. It is code someone else already wrote for us, and it is where printf comes from. Lines starting with # are special, and they don’t end with a semicolon.
int main(void) Every C program starts running at main. The int means main gives back a whole number when it finishes, and void means it takes nothing in.
{ and } Everything between these two curly braces belongs to main.
printf("Hello, world!\n"); Prints the text between the quotes. The \n is not printed as it is. It means “go to a new line”.
return 0; Ends main and hands 0 back to the operating system. 0 means everything went fine.

Statements end with a semicolon

One instruction in C is called a statement. printf("Hello, world!\n"); is a statement, and so is return 0;.

Every statement ends with a semicolon ;. It is the full stop of C. Forget it, and the compiler stops. Here is the same program with the semicolon after printf missing:

    printf("Hello, world!\n")
    return 0;
Compiler errorhello.c: In function 'main':
hello.c:4:30: error: expected ';' before 'return'
    4 |     printf("Hello, world!\n")
      |                              ^
      |                              ;

Read errors from the top. hello.c:4:30 means file hello.c, line 4, character 30. The compiler even draws an arrow where the semicolon should go. Errors look scary at first, but most of the time they tell you exactly what is wrong.

Curly braces make blocks

A pair of curly braces { } groups statements together into a block. The body of main is a block. Later, when we learn about if and loops, they will have blocks of their own.

The rule is simple: every { needs a matching }. If you open one and never close it, the compiler will complain.

Spaces and new lines mostly don’t matter

The compiler doesn’t care about extra spaces, tabs or empty lines. This program works exactly the same as the first one:

#include <stdio.h>
int main(void){printf("Hello, world!\n");return 0;}

But it is painful to read, so nobody writes code like that. We put each statement on its own line and push the lines inside a block a bit to the right. That push is called indentation, and it is only there for humans.

There are a few places where spaces do matter:

  • Between two words. int main works, intmain doesn’t.
  • Inside quotes. "Hello, world!" and "Hello, world!" print different things.
  • Lines starting with # must sit on a line of their own.

Comments

A comment is a note for humans. The compiler throws it away, so it never affects the program. C has two kinds:

// This is a one line comment. It lasts until the end of the line.

/* This is a block comment.
   It can go over as many lines as you want,
   and it ends here: */

return 0; // A comment can also sit after code.

You can’t put a block comment inside another block comment. The first */ ends the whole thing, and whatever comes after it is treated as code.

Capital letters matter

C is case sensitive. To C, main, Main and MAIN are three completely different words. If you write Printf instead of printf, C has no idea what you mean.

Rules for names

Soon we will give names to our own things, like a variable that stores a score. A name you make up is called an identifier, and it has to follow these rules:

  • It can use letters, digits and the underscore _.
  • It can’t start with a digit.
  • It can’t have spaces or symbols like -.
  • It can’t be a keyword. Keywords are words C already uses for itself, like int, void, return, if, else, while and for.

Recap

  • Syntax is the grammar of C, and the compiler refuses code that breaks it.
  • Every program starts at main.
  • Every statement ends with ;.
  • Curly braces { } group statements into blocks, and they always come in pairs.
  • Extra spaces and new lines are for humans, not for the compiler.
  • Comments use // or /* */ and are ignored by the compiler.
  • Capital letters matter, and names follow strict rules.

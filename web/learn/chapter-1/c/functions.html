Instead of reusing the same block of code again and again, we use something called functions. For example, somebody way back—like literally wayyy back—wrote the printf function to print something to us in the terminal. So we just import that function and use it whenever we want. In this lesson, we will be doing exactly that.

By default, whenever we run our C program, we execute the main function. The main function is a special function and runs automatically every time we run the program. Other functions don't run automatically unless we call them.

As you can probably guess, main is not the program itself, it's just a function. And the main one!

In C, you need to define functions by specifying what the function will give back (return) when it's done. Our function will just print something and won't give anything back, so we use void, which simply means "nothing". We will see functions that do give something back later in this lesson.

So our function written so far: void

Then we write the name of the function. Let's call this function hello.

So our function so far: void hello

Then we use a pair of parentheses, (), to tell the program that we are talking about a function. The program needs to differentiate between a variable and a function, and inside these parentheses, we can pass something called arguments (we will come back to these at the end of this lesson).

So our function so far: void hello()

Then we have something like walls: the curly braces, {}. Inside these, we write whatever we want to happen when this function is called. For now, whenever this function is called, let's just print "hello". To do that, we need to call the printf function. (The 'f' in printf stands for "formatted"). Inside the printf we will pass an argument—something known as a string, which we will come back to soon as well.

But wait! Remember that printf is written by somebody else, so we need to import the library or file that contains it. That is done using the #include line, and it generally goes at the very top of the file.

So our code so far:

#include <stdio.h>
void hello() {printf("hello")}

Now, we generally like to keep our code organized, so we write each instruction on a new line. Like this:

#include <stdio.h>

void hello() {
    printf("hello")
}

Now we are missing something. Recall that every instruction in C—except for defining functions and importing files—needs to end with a semicolon. That's just the rule.

So our code so far:

#include <stdio.h>

void hello() {
    printf("hello");
}

Now let's save this as hello.c, compile it (using make hello), and then run it (./hello).

Wait! You might expect this program to compile successfully, but it won't! It will actually give you an error.

Why? Because whatever is in main gets executed first. If the program doesn't find main, it panics and gives an error because it doesn't know where the program is supposed to start. Our code right now only has hello.

If we didn't want anything to actually happen, we could just leave the main function empty. But we do want something to happen: we want our hello function to run. So, before finishing our script, we will write our main function and call our hello() function inside it. We are calling our new function exactly the same way we called the printf function earlier!

Here is what the final, working code looks like:

#include <stdio.h>

void hello() {
    printf("hello");
}

int main() {
    hello();
}

Now, when the program runs, it starts at main, sees that we are calling hello(), jumps up to our hello function, prints "hello", and finishes successfully!

Now notice that we wrote our hello function above main, not below it. That's on purpose. C reads your code from top to bottom, just like you do. So if hello were written below main, by the time C reaches hello(); inside main, it has never heard of hello before. Newer compilers will give you an error and refuse to compile it. Older ones will only give you a warning and take a guess, but you should never rely on that guess. Our challenge checker treats it as an error, just like the newer compilers.

So what if you really want main at the top? Well, you can tell C about the function before using it, by writing just the first part of it at the top of the file, followed by a semicolon. This is called a declaration. Notice the semicolon: we are not defining the function here, we are only telling C that it exists.

#include <stdio.h>

void hello();

int main() {
    hello();
}

void hello() {
    printf("hello");
}

Now C already knows about hello by the time it reaches main, so it's happy, even though the actual code of hello is written at the bottom.

Giving something back: return

So far, our function just does something and that's it. But a function can also give a value back to whoever called it, using return. This time, instead of void, we write the type of the value it gives back. For example, this function gives back the number 1337, so its type is int:

int leet() {
    return 1337;
}

int main() {
    int x = leet();
    printf("%d\n", x); // prints 1337
}

When C reaches return, the function stops right there and hands the value back. So int x = leet(); stores 1337 in x, just like writing int x = 1337;.

Passing something in: arguments

Remember the arguments we skipped earlier? Arguments are values you hand to a function, so it can work with them. You have already done this with printf: in printf("hello"), "hello" is the argument. To make our own function take an argument, we write it inside the parentheses, with its type and a name, just like declaring a variable:

int square(int n) {
    return n * n;
}

int main() {
    printf("%d\n", square(5));  // prints 25
    printf("%d\n", square(12)); // prints 144
}

Every time we call square, n becomes whatever we passed in: 5 the first time, 12 the second time. A function can take more than one argument too, separated by commas:

int add(int a, int b) {
    return a + b;
}

And add(2, 3) gives back 5.

One more thing: variables you create inside a function only exist inside that function. The n in square has nothing to do with an n in main. Every function has its own.

So what is return 0?

Remember the return 0; in our very first program? Now you know what it means: main is a function too, and it returns an int. But who does it return it to? The system that ran your program! 0 means "everything went fine", and any other number means something went wrong. You can even see it yourself: run your program, then run echo $?, and it prints the number your main returned.

And if main doesn't have a return at all, C returns 0 for you, which is why our programs work fine without it.

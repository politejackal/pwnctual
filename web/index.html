psychology_altWhat we check

AI writes code that works.
Not code that's secure.

AI tools make the same mistakes over and over, because they aim for "it runs" and stop there. These are the ones we see the most.

key

Secret keys in the browser

The AI put your API key in the frontend because that's where the code needed it. Anyone can open DevTools and copy it.

database

A database anyone can read

Supabase and Firebase have access rules you're supposed to turn on. AI often skips them, so your public key is enough to download every row.

api

APIs that skip the login check

The page hides the button from logged-out users. The API behind the button still answers anyone who calls it.

pin

Other people's data, one number away

/api/orders/1042 shows your order. /api/orders/1041 shows a stranger's, with their address.

admin_panel_settings

Admin pages with no lock

Your /admin page isn't linked anywhere, so it feels hidden. Bots try that URL on every site they find.

bug_report

Stuff left over from building

Source maps with your full code, debug pages, test accounts, and that .env file that got deployed by accident.

CriticalAnyone can read every customer's name, email and addressexpand_more
WHAT WE FOUND

The customers table in Supabase has row level security turned off. The public key in your frontend is enough to download the whole table: 1,284 rows.

PASTE THIS INTO YOUR AI TOOL
Turn on row level security for the customers table in Supabase. Add a policy so a logged-in user can only select, update and delete rows where customers.user_id = auth.uid(). Don't add any policy for anonymous users.
CriticalStripe secret key is in the JavaScript sent to every visitorexpand_more
WHAT WE FOUND

A key starting with sk_live_ is in /assets/index-8f3a1c.js. With it, someone can issue refunds, read your payments and see your customers in Stripe.

WHAT TO DO FIRST

Roll the key in the Stripe dashboard right now. Then fix the code.

PASTE THIS INTO YOUR AI TOOL
Move every Stripe call that uses the secret key into a server-side function. The frontend should only use the publishable key (pk_live_). Read the secret key from an environment variable that is never bundled into client code.
HighChanging the order number shows someone else's orderexpand_more
WHAT WE FOUND

Logged in as a test user, /api/orders/1042 returned our order. Changing it to 1041 returned another customer's order, including their phone number and delivery address.

PASTE THIS INTO YOUR AI TOOL
In the GET /api/orders/:id handler, check that the order belongs to the logged-in user before returning it. If it doesn't, return 404. Do the same for every route that takes an ID.
MediumUnlimited password attempts on the login pageexpand_more
WHAT WE FOUND

We sent 500 wrong passwords for one account in a minute and none were blocked. A bot can keep guessing until it gets in.

PASTE THIS INTO YOUR AI TOOL
Add rate limiting to the login endpoint: at most 5 failed attempts per account per 15 minutes, and at most 20 per IP address. Return 429 when the limit is hit.
